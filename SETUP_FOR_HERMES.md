# Hermes Agent Self-Setup Prompt

Copy the prompt below and paste it into your Hermes WebUI (or any Hermes chat surface).
Your Hermes agent will set up the Sendblue SMS/iMessage bridge for you.

---

## Prompt (copy everything below this line)

```
Set up the Hermes Sendblue SMS/iMessage bridge for me. Follow these steps:

## Step 1: Prerequisites check

Run these checks and report what's missing:

- Node.js: `node --version` (need 18+)
- npm: `npm --version`
- Hermes Agent: verify `~/.hermes/hermes-agent/venv/bin/python` exists
- aiohttp: `~/.hermes/hermes-agent/venv/bin/python -c "import aiohttp"` (install with pip if missing)

If anything is missing, tell the user what to install and stop.

## Step 2: Clone the repo

```
cd ~/workspace 2>/dev/null || cd ~
git clone https://github.com/codebooker/hermes-sendblue-bridge.git
cd hermes-sendblue-bridge
```

If the repo URL doesn't work yet, clone from where the user tells you.

## Step 3: Install dependencies

```
npm install
```

## Step 4: Get Sendblue credentials

Ask the user (use clarify tool):

"Do you already have a Sendblue account with a phone number?"

If NO:
  Tell them: "Go to https://sendblue.co/sign-up and create an account. The free tier works.
  Once you have your API keys and phone number, come back and tell me."
  STOP and wait.

If YES, ask them to provide:
  - Sendblue API Key ID (from Dashboard → API Keys)
  - Sendblue API Secret Key (from Dashboard → API Keys)
  - Sendblue phone number (the one people will text, E.164 format like +14081234567)

Generate a strong Hermes API key:
```
openssl rand -hex 32
```

## Step 5: Create .env file

Write .env with this exact content, using the values the user provided from Step 4 and the generated hex from Step 4:

```
# Sendblue -> Hermes bridge configuration
# Generated by Hermes self-setup
SENDBLUE_API_KEY_ID=<their_key_id>
SENDBLUE_API_SECRET_KEY=<their_secret_key>
SENDBLUE_FROM_NUMBER=<their_sendblue_number>
SENDBLUE_WEBHOOK_SECRET=<generated_hex>
HERMES_API_SERVER_URL=http://127.0.0.1:5000/v1
HERMES_API_SERVER_KEY=<generated_hex>
PORT=5000
```

Use the write_file tool. Both SENDBLUE_WEBHOOK_SECRET and HERMES_API_SERVER_KEY
can use the same hex output from `openssl rand -hex 32`. Replace <placeholders>
with the actual values the user provided.

## Step 6: Set up personality config

Open sendblue-bridge-polling.js and help the user configure the personalityConfig section.
Ask them:
- What's their own phone number? (for a personal/friendly personality)
- Any other contacts they want to add?

Edit the personalityConfig object in the JS file. The format is:

```js
'+1<their_number>': {
  name: '<name>',
  systemPrompt: `You're chatting with <name> over text. Be casual and friendly.
    Use web_search for any factual/current questions. Keep responses brief.`,
},
```

Use the patch tool for these edits — don't rewrite the whole file.

## Step 7: Configure systemd services

Set up user systemd services so the bridge runs persistently:

```
mkdir -p ~/.config/systemd/user

# Copy service files, replacing %h with actual home
for svc in hermes-api-bridge.service sendblue-bridge.service; do
  sed "s|%h|$HOME|g" systemd/$svc > ~/.config/systemd/user/$svc
done

systemctl --user daemon-reload
systemctl --user enable hermes-api-bridge.service sendblue-bridge.service
systemctl --user start hermes-api-bridge.service sendblue-bridge.service
```

NOTE: If systemd --user isn't available (container, WSL, etc.), instead tell the user to run:
```
./start-sendblue.sh &
```
And note that they'll need to restart it manually after reboots.

## Step 8: Verify

Wait 3 seconds, then check:

```
systemctl --user status hermes-api-bridge.service --no-pager
systemctl --user status sendblue-bridge.service --no-pager
curl -s http://localhost:5000/health
```

If both services show "active (running)" and the health check returns {"status": "ok"}, it's working.

## Step 9: Final instructions

Tell the user:

"✓ The Sendblue bridge is running. Text your Sendblue number (<number>) to test it.
Your Hermes agent will reply with full tool access (web search, memory, etc.).

To customize how it responds to different contacts, edit the personalityConfig in:
  ~/workspace/hermes-sendblue-bridge/sendblue-bridge-polling.js

To view logs:
  journalctl --user -u sendblue-bridge.service -f

To stop:
  systemctl --user stop sendblue-bridge.service hermes-api-bridge.service"

IMPORTANT RULES:
- Never hardcode user-specific paths. Use $HOME or ~.
- Never commit the .env file (it's in .gitignore already).
- If any step fails, explain the error clearly and suggest a fix.
- The API bridge must have 'memory' in its toolsets for SMS context to work.
- If running the systemd services fails because systemd --user isn't available, just use the start-sendblue.sh script and tell the user they'll need to restart after reboots.
- Do NOT ask the user to run commands themselves — YOU execute them via terminal tool.
```

## Usage

1. Open your Hermes WebUI
2. Copy the prompt above (from "Set up the Hermes Sendblue..." through the end)
3. Paste it as a message
4. Hermes will walk you through the setup, asking for credentials when needed

The entire setup takes about 5 minutes end-to-end.
